# DeepDocParse-Web / frontend

Vue 3 + TypeScript + Router + Pinia + Element Plus。用 `npm create vue@latest` 生成，未手写工程配置。

```bash
npm install
npm run dev          # 5173，/api /files /v1 /mcp 已代理到 http://127.0.0.1:8080
npm run build        # 含 vue-tsc 类型检查
```

## 页面

| 路由 | 内容 |
|---|---|
| `/login` | 登录 / 注册（开放注册，无邮箱验证） |
| `/documents` | 概览卡片 + 筛选（文件名/解析状态/问答状态）+ 分页 + 批量选择；行内可下载/重解析/重建索引/删除 |
| `/documents/:id` | 三栏工作台：pdf.js 原文 + bbox 高亮 ／ 按页结果 ／ 问答面板 |
| `/documents/:id/versions` | 解析版本对比、换参数重解析、设为当前 |
| `/search` | 跨文档检索，命中带页码可直达 |
| `/keys` | API key 签发（明文只显示一次）、额度/限速/有效期、吊销 |
| `/usage` | 用量卡片网格：统计卡 + 每日趋势图 + 按平面汇总 + 按天明细 |
| `/settings` | 账号信息（`/api/auth/me`）+ 本机默认解析参数 |
| `/tasks` / `/tasks/new` | 联邦任务列表 / 发起任务：资料节点与仅算力接收方逐项勾选，Wiki 需求类型化输入 |
| `/tasks/:id` | 审阅生成执行者与全部有向数据边，批准并执行后查看出处或已提交的 Wiki 修订 |

工作台的 PDF worker 随产物本地部署为 `.js`（兼容 nginx 默认 MIME），不依赖 CDN。
每个加载任务独立拥有 worker；切换原件或卸载视图后，迟到的加载不再创建线程或替换当前结果。
从检索命中跳转或重新打开原件时，旧视图销毁不会阻塞新视图；命中失效只提示定位失败，
仍显示已固定版本的原件，不伪造高亮。

### A 入口、B 资料、C 生成的浏览器流程

前提：A 的管理员已批准可见的 B、C；描述租约未过期。B 发布集合，C 可没有集合；
生成能力目录只读取已批准且描述新鲜的直接成员，不把未知健康状态当成就绪。

1. 在 A 登录后打开 `/tasks/new`，填写问题，选择“带出处的回答”，选择“联邦公开范围”并点击“生成范围清单”。
2. 在“资料节点”手动勾 B，在“仅算力节点”手动勾显示可用且接单的 C。节点从不自动勾选；
   未知、不健康、排空、不接单或观测过期的仅算力节点不可选，点击“刷新生成能力”重新观测。
   观测失败不会显示为“没有候选”，仅算力选择会清除并明确提示；切出联邦范围后再返回，
   必须重新生成范围清单。观测时间允许与生产者相同的 5 秒偏移，超过时显示不可确认的原因。
3. 检查外发许可的接收方与载荷，明确允许问题原文和证据摘录，确认探测次数与字节预算，
   点击“创建任务并规划”。范围清单和能力观测都不是执行授权。
4. 详情页检查“生成执行者”是否为 C，并逐条审阅
   A→B `query_text`、B→A `evidence_excerpts`、A→C `evidence_excerpts`，
   含中继、保留策略、有效期与预算。回答通过执行者状态返回 A，现有计划没有单列
   C→A `answer_text` 边；Wiki 则有显式的 C→A `wiki_draft` 返回边。
   规划器决定生成位置，勾选 C 不是强制派给 C；位置或边不符合预期时不要批准。
5. 点击“批准并执行”，完成后在同一任务详情查看带原始出处的回答。

Wiki 使用相同的范围、接收方与两层许可流程：第一步改选“构建 Wiki 草稿”，新建和更新都必须
填写标题与 1–12 页的上限；更新还必须填写 Wiki 编号和基于修订编号（CAS）。批准卡片中会并列
展示生成步骤的操作名、执行节点和全部数据边；确认 C 的 `wiki_pages`
生成步骤与 C→A `wiki_draft` 返回边。C 只生成，A 校验后提交；任务详情的 Wiki 面板展示
已提交的修订，而不是把远端草稿当成已保存结果。没有生成步骤时界面明确说明，不伪造产物。
Wiki 任务的结果区显示“Wiki 生成”并指向下方“Wiki 修订”，不再宣称任务只取证据；
生成失败时保留现有原因标签和原始细节（如校验拒绝码或耗尽预算时的轮询次数）。


## 架构约定（加功能前先看这里）

- **加页面**：只在 `router/routes.ts` 加一条并写 `meta`（`title/icon/group/nav`），
  侧边栏会自动出现该项 —— `layouts/AppShell.vue` 从路由派生菜单，不要去改导航代码
- **加接口**：在 `api/` 下按域加模块并挂到 `api/index.ts`；类型放 `types/api.ts`
- **加状态值**：解析/索引状态、问答降级说明统一在 `constants/status.ts`，
  改一处全站生效（标签、筛选下拉、气泡文案都由它派生）
- **加解析引擎或参数**：只改 `constants/engines.ts` 的 schema，
  上传对话框与重解析共用 `components/engine/EngineOptionsForm.vue`，两处同时生效
- **轮询**：用 `composables/usePolling.ts`，不要再手写 `setInterval` + 清理
- **页面文件加载失败**：全局路由错误处理会持续显示「界面文件已变更或缺失」，
  并提供「重新加载窗口」。浏览器与桌面都只在用户点击后重载，不自动重载或重试；
  重载后仍失败时，检查网络或安装文件是否完整。
  普通导航异常保留控制台诊断并只显示一条持续提示；守卫中止、重定向不作错误提示。
- **文件任务上传说明**：上传回执未确认完整摘要时只显示等待确认，不断言中心仍在校验。
  对账取得与原件及上传记录一致的中心输入校验记录后显示「输入已通过服务端校验」；
  即便交付已确认，这一行也始终说明「上传不是解析完成」。

## 两个必须知道的约束

1. **渲染结果必须过 DOMPurify**（`src/utils/markdown.ts`）。markdown 来自被解析的文档，
   是不可信输入；`markdown-it` 已关 `html`，再 sanitize 一遍是第二道闸。
2. **图片走 blob 而不是直接 `<img src>`**。归档后的 markdown 里图片指向
   `/api/tasks/{id}/images/{name}`，该端点受 JWT 保护，而 `<img>` 发不出 Authorization 头 ——
   `resolveAuthedImages()` 渲染后按需取回并换成 object URL。好处是归档产物里不埋任何凭证。
