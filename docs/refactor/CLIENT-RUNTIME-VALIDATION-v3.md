## 已修复的失败

OpenCode / DeepSeek 只读审查发现：健康连接之间不恢复重试预算、确定尚未发送的请求遗留不明意图、已确认历史请求占满未决请求额度。分别通过持续健康窗口重置、发送前身份检查时清除确定未发送的意图、分离未决额度与确认回执保留规则修复，均有负向回归。

后续检查补了公开描述符可复制的问题：发送凭证前验证随机挑战、Ed25519 私钥持有证明、节点公钥摘要及配置端点绑定。Go 控制服务与真实 TypeScript HTTP provider 的互通验证由 discovery 验证记录负责。

浏览器测试抓到刷新会丢掉组件防抖计时器内草稿。现每次编辑立即排入主进程持久写入；只有成功确认才显示「已保存」。写请求需要先成功保存操作编号。连接切换前等待所属草稿保存，CAS 冲突可见。

完整回归进一步证明「立即加入renderer promise队列」仍不等于「已经送到main」：Wiki切换页字段产生多项等待确认的保存，刷新时最新文本可能尚未发送。现在共享 `DraftWriter` 在编辑同步回调内立即invoke，以预测的连续修订维持CAS；主进程按IPC到达顺序同步提交SQLite。任何失败或异常修订使当前writer停止写入，不能静默重基准覆盖另一窗口。3个确定性单测覆盖迟到确认/失败/异常修订，最新9项工作台和89项整套浏览器通过。关闭进程前未得到持久确认的写仍不声称已保存。

独立审查还抓到清除凭证被早先磁盘读取复活，以及连接关闭后命令/回执仍返回旧代次数据。凭证按身份串行化并加会话代次；写结果先归档原身份回执再检查当前代次。相同审查者复验原凭证竞态100次零复活，迟到结果返回disposed且保留确认回执，详见 `DESKTOP-INDEPENDENT-REVIEW-v3.md`。

## 有意区分的状态

连接状态不代表投影新鲜度；断线缓存标为 stale。回执表示受理或已有记录，不表示计算成功或交付验证完成。缺失回执不能证明服务器从未受理。重连只恢复订阅和查询，不重放创建、生成或删除。缓存清理保留身份绑定、草稿与写入对账记录，也不会删除用户资产。

SQLite 缓存为主进程私有文件，使用 WAL/FULL 同步提交、代次和游标 CAS、64 MiB 数据库上限、每条投影/回执 4 MiB 上限。每个身份最多保留 128 条完整确认回执，较旧回执保留请求摘要墓碑；未决意图单独上限 10,000。超限是可见失败。
