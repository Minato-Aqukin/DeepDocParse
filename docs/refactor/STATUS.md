## 第一次真起全栈的账（2026-09-02）

**这一步的收益远超预期。** 当时的状态是：全部单测绿、全部守卫绿、
四条 CI 工作流绿、`./scripts/check.sh` 21/21 绿，独立验收也走完了。
然后第一次 `docker compose up`，连着抓到**七个让产品主链路完全不通**的缺陷
（`FINDINGS.md` F-17..F-23）：

1. 给浏览器签名的对象存储 client 在签名前要先连一次那个 endpoint（容器里连不上）
2. 迁移建的数据库角色没有口令，服务连不上库
3. outbox 投递只发了一半的 actor 上下文头，事件永远 401
4. 语料表在 `public` 而授权写的是 `corpus` schema —— 那段 SQL 从未执行过，
   于是"Go 对语料一个字都写不了"这句话在真部署里从来没生效
5. 解析平面**根本没有 worker**（旧 compose 的 arq-worker 合仓时整个漏掉）
6. 稳定文件 URL 签的是浏览器地址，而下载它的是容器里的进程
7. 语料侧 outbox 只有写入端没有投递端，用量与账单永远是空的

七个的共同形状：**每个容器都 healthy，每一层都"正确地"报错，
而端到端一次都没通过。** 进程内测试原理上看不见它们。

固化：`scripts/e2e_stack.py` + `.github/workflows/stack.yml`
（起真容器跑真实用户路径），以后每次 push 都会跑。
