## 4. 从逻辑资源到稳定证据

中心语料域 ER 视图，非本机 SQLite 表结构。Resource 是有 owner_id、organization_id、publication 等属性的逻辑资产；Document.id 是数据库主键，doc_id 是内容 SHA-256，去重约束为 (doc_id, origin, organization_id)，不能据共享字节推导共享权限。Resource→ResourceVersion 为一对可多条版本；多条版本可引用同一 Document。每个 ResourceVersion 存 document_id、version_no、source_digest 与可空 parse_job_id；图中 N:0..1 表示每个版本最多绑定一个解析，多个版本可绑定同一解析，并非版本和 ParseJob 一对一。parse_job_id 为空表示未冻结解析，绝不回落到 Document.current_job_id；该字段为应用层绑定而非本模型定义的数据库 FK。Document 可有多 ParseJob，唯一约束为 (document_id, resource_id, options_hash)，ParseJob.resource_id 可空，所以不能宣称同字节全局只解析一次。Document.object_key 是原件；ParseJob.result_prefix 是解析归档产物。ParseJob 可有多 Evidence，以 (parse_job_id, atom_key) 唯一；Evidence 保存 page_idx、bbox、page_size、content_digest、provider 等稳定定位。derived_from 是 Evidence 的可空自引用：派生证据指向源证据，不把模型理解混为源原文。Citation.evidence_id 为 FK，每个 Citation 指一条 Evidence，Evidence 可被引用多次；source_kind/source_id 是引用主体，Citation.content_digest 记录该次引用看到的内容，不等同于 Evidence 首次锚定摘要。线旁 1:0..N 包含尚未有解析、证据或引用的阶段。Chunk 按 (document_id, parse_job_id, seq) 组织，是可重建缓存，其随机 ID 不能充当稳定引用锚。来源均为 models.py 所列范围；图中关系方向沿业务理解顺序，并非全部等同 FK 指向。

## 5. 文件入库：摘要核验与异步编译索引

中心永久资料上传时序；不是 gateway 临时文件计算链。六列区分客户端、Go 控制面、MinIO、Python 语料域及其 PG tasks、gateway-worker 解析执行和 corpus-worker 索引执行。客户端先 POST /api/uploads 获得 multipart 会话与分片 URL，直传 MinIO；finalize(parts, engine, options) 完成 multipart 并 HEAD 核对大小，状态进入 verifying，不在此时写 DocumentSubmitted Outbox。若完成回执不明，先 Stat 已有持久对象键。控制面后台流式读取整个对象计算 SHA-256；只有 MarkUploadVerified 在同一 PG 本地事务中写 upload ready 与 DocumentSubmitted Outbox。图中第⑤箭头合并展示同事务落库与随后事件传送，绝不是跨服务同事务。Outbox 至少一次投递 /internal/events，只携带元数据、对象键和已验证摘要；corpus 以 processed_events.event_id 幂等占位，409 duplicate_event 被投递器视为 ACK。corpus 落 Document/Resource/ResourceVersion/ParseJob 后，向 control 申请绑定源对象的稳定 /files/{token}，再经 model-gateway 提交解析。解析执行列概括 model-gateway→Redis/ARQ→gateway-worker→具体引擎；它与 PG 持久索引队列不是一套 worker。解析回调由 corpus 取回并永久归档结果，然后 index_status=pending，enqueue(kind="index", payload={document_id,job_id}) 并提交。第⑧是 corpus-worker 从语料域 PG tasks 领取任务，不表示 corpus API 同步调用 worker。index_document 固定 ParseJob claim，内部调用 compile_document 与 embedding；当前 handlers 无独立 compile handler。持久写 Evidence/Chunk 前锁 Document→ParseJob，重验 ParseJob.index_generation 与 indexing 状态，以及资源、固定版本、原件授权；仅替换该 job 的 Chunk。PG 队列自身另以 task id + generation + 活跃状态围栏，claim 使用 FOR UPDATE SKIP LOCKED，不能用 worker 名代替提交资格。Document 当前状态只在 current_job_id 匹配时镜像更新。灰虚线仅为时序生命线。

## 6. 统一布局，分离原文与检索增强

中心解析/编译机制图。ParseEngine 统一 submit/status/fetch_result 三步；resolve 显式分派 mineru-api、borndigital、borndigital-tables、vlm-ocr，未知/缺失 runtime 直接失败，不自动切 MinerU。MinerU 外部结果经 from_mineru，文字层引擎经 build，VLM OCR 页面渲染后经 build_pages，均归一为 DDP-Layout；引擎并不直接写语料 PG。图中汇合箭头代表契约适配，不代表四种引擎必须全部执行。DDP-Layout layout_version="ddp-layout/1"，页级 page_idx/page_size/para_blocks/printed_page_label，块级 type/bbox/lines。八种 type 是 text/title/table/figure/equation/code/list/other，旧示例“七值”注释不沿用。表格原始结构位于 spans[].html，不能说 Layout 块顶层有 table_html；编译递归提取后才有 Chunk.table_html。page_idx 为 0 基物理页，bbox=[x0,y0,x1,y1] 左上原点、PDF 点单位，与包含旋转的 page_size 同基准；印刷标签仅显示，不改变物理页定位。chunking 有坐标/尺寸守卫与页内几何邻接，不跨页，代码/表格/公式/图独立；bbox 缺失并不使整块无效，长块切分可能继承原块 bbox，因此不是精确句子框。永久 Layout 由 corpus archive_job 归档，之后 index_document 读取固定 ParseJob 的 layout.json 并编译。共享 compile_chunks 不修改源 text；search_text 可追加公式别名、同页上下文、表格 HTML 与视觉 derived_text。视觉裁图与受限并发 VLM 理解在中心 corpus 适配器显式执行，再注入共享编译器；不是 ddp_core 隐式发网络请求。索引中原文 Evidence 与派生 Evidence 分开，后者 derived_from 指向源证据。本图不将中心多模态与本机默认文字层 CPU 解析能力混同。

## 7. 按名次融合，给每个问题切面留位

中心授权固定解析集合内的混合检索，不描述本机 SQLite 默认检索。授权 document_id/parse_job_id 进入 SQL 范围；dense 用 pgvector <=> 余弦距离。查询包括原问题、最多三条显式 query_variants，以及 _query_facets 对明确英文并列问句保守识别的 2–4 个合格切面；不是任意 LLM 自动分解。批量 embedding 失败时 vector=None 并标 embedding_unavailable，不伪造零向量。keyword 共享索引/查询 tokenizer，以 OR 召回，按命中词在授权块集合的 Σ1/df 排序，不是 BM25、也不是简单 ts_rank；其 savepoint 隔离失败并标 keyword_unavailable。每个查询内部 RRF(c)=Σ_l 1/(60+rank_l(c))，rank 从 1 开始；真实排名输入为 dense、keyword、exact-code、exact-code，exact-code 重复两次。代码精确路只从关键词候选中过滤 code 块并排标识符，不是独立全库第三次扫描。不同查询融合结果按排名列表轮转占位，按 chunk_id 去重并保留最高可用 similarity；当切面数达到最终 limit 时，切面优先于原问题，避免最后一面被挤掉。不是对所有切面结果再做一遍全局 RRF。QA 下游先 gate_candidates，再可选 _seeded_rerank；多表达对同一池精排并轮转选独立主题种子，一路失败则整体回退混合池序并标 rerank_unavailable。adjacent_context_hits 只补已选种子的同页续块，不挤掉其他主题种子，字符预算耗尽即停。融合分与 cosine similarity 量纲不同；邻接只补上下文，不构成相关性或语义证明。

## 8. 完整主张闭合后，才进入答案流

中心 QA 实际时序。入口 conversations.py 先授权并构造固定解析上下文，经 decide_retrieval 选择 retrieve 或 inherited_retrieval；继承 Evidence ID 失效时明确拒答，不让空上下文模型用常识补答。trim_hits_to_context、attach_crops、build_messages 后，仅把模型真实可见正文对应的 Evidence ID 放入允许集合；原文和生成理解分条，分别携带 evidence_id/source_type/derived_from，表格正文优先 HTML，预算选择后恢复物理阅读顺序。图中的“结构化生成器”包含上游 chat 与 GroundedAnswerStream 解析器，不表示模型自行负责持久授权。生成器实际线协议只返回 claims/unanswered，claim 含 text/evidence_ids；示例为协议示意，evidence-id 必须替换为该次模型可见集合中的真实 ID。模型不返回 status、verified 或公共 citations。GroundedAnswerStream.feed/finish 拒未知或重复键、非法 ID、空引用和截断；每个 claim 完整闭合且合法后才释放 SSE delta，而不是把未解析 token 原样流给用户。unanswered 只在 finish 完整成功后投影为无引用、unsupported=true 的展示项，不伪造成有支持主张。随后 _persist 在独立 session 重验权限与索引 generation，写 Message、Assertion、Citation 及核对记录；逐 Assertion 依请求 ID 写 Citation(source_kind="assertion")，持久失败则收紧为 unsupported。消息级 citations 取实际持久 Assertion 引用的有序并集，不附上全部检索候选。落库后发送 SSE citations、assertions、done。图中第⑤箭头覆盖独立持久化过程；持久结果返回编排层，由编排层发第⑥完成事件，数据库本身不发 SSE。源 Evidence 的 verify_pair 核对是图文转录一致性；只有断言全部引用都在已通过核对集合内才 passed，其他证据/派生理解不能继承。消息 verified 仅是全断言有支持且 passed 的兼容投影，不是语义蕴含证明，人工语义复核仍未自动完成。灰虚线仅为时序生命线。

## 9. 字段带出处，数值有主出处见证

中心结构化抽取机制，图右上为内部模型协议示例，不是最终公共字段对象。validate_schema 仅允许 string/number/integer/boolean 平坦叶子，description 必需；外形可为对象或顶层记录数组，叶子嵌套 object/array 拒绝，format/enum 为有界支持。字段名、description、显式位置词共同检索；精排与混合头交替留种，_fill_field_context 先补完整连续区域、最多 2*k 块，再同页邻接至最多 3*k，并受字符预算约束，不截断区域凑数。原文与派生视图分离。对象内部生产协议如 {found:true,value:3,support:{value_source:1,context_sources:[2]}}，value_source/context_sources 是该次上下文资料编号，不是公共 Evidence ID 或 Citation 对象。先做 support 角色校验、类型/enum/format 校验；对象 number/integer 字段再只对 value_source 主出处做精确数字见证，context_sources 不可救援主出处缺数。类型转换和见证共享数字词法，Decimal 精确归一千分位、小数、科学记数法，拒非有限、歧义、非法千分位及标识符/点分版本伪数量，不用浮点容差；不做单位换算、算术或主体语义证明。当前记录数组 _record_field 只做类型转换，未调用此对象数值见证，每行生产器用 {source:1,values:{用户列}}，坏指针只丢该行；不能宣传守卫覆盖全部模式。外部字段键为 status/value/citations/verified/degraded/confidence，status ∈ found/not_found/error；无候选或明确缺席为 not_found，上游故障、坏结构、类型/见证失败为 error，不能掩成文档无资料。可选裁图核对仅当所选全部出处确实一致才 verified=true，核对不等于主张语义已被人工复核。图中虚线只代表可选视觉核对支路，其结果回并公共输出，非必经步骤。

## 10. 先冻结证据，再追加可回溯修订

中心 Wiki 选证、修订及派生状态图。freeze_sources 先授权固定成功解析与版本，只选该版本索引中的原始 Evidence。标题规划最多三条查询，焦点队列先于通用标题；每源混合检索/可选精排，切面与来源轮转、完整区域补齐，每个请求来源须有代表。max_evidence/max_input_chars 按实际序列化输入含 table_html 计量，非全文无界塞入模型；查询规划输出预算也从总输出预算扣。恢复物理阅读序后才做页面规划和写作/关系预算。服务端构造 q1.1 等原文 support-span 目录，模型仅选 support，服务端据 span 物化 Evidence ID 与引文，验证原文归属；不是让模型通过第二组 ID 猜绑定，机械引文存在也不证明语义正确。写入 WikiRevision/WikiPage/DependencyManifest/ClaimEvidenceBinding；依赖含固定版本、parse_revision、evidence_id、excerpt_digest、locator，且保守包含进入写作的全部冻结上下文，即使未被引用也保留，避免私有资料借公开引文被洗掉，人工页保留旧依赖。append_revision 后条件更新 Wiki.current_revision_id == base_id，以 CAS 失败 409 阻止覆盖并发改动，不原位改历史。人工编辑同样追加 revision，段落 kind=human,unsupported=true；重建按 page_key 保留人工段落，若新计划缺页则保留整旧页并记冲突，超页预算拒绝。草稿可在依赖与质量门通过后 CAS published_revision_id；stale/冲突/无支持均阻止发布。stale 是依赖实时派生状态，不是写坏历史 revision；来源版本、解析绑定、摘要变化触发，对同页同资源已有最新依赖的历史兼容情况有处理，不会仅因保留历史依赖永久 stale。公开读取和发布重新检查依赖；owner 可见 stale 提示，非 owner 公开读取不可见。撤销来源另清发布指针及 Wiki 缓存。状态框合并表达禁止公开的几类门禁，非宣称数据库有一个同名枚举；“CAS 成功→草稿”是写 current 指针后的逻辑状态。人工语义复核没有被系统自动完成。
