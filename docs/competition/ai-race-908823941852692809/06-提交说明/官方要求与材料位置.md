# 官方要求与材料位置

依据官方[作品提交说明](https://aerate.s3.cn-north-1.jdcloud-oss.com/material/6ab9e99ee4b0e7f3eda65569.pdf)和[时间调整通知](https://aerate.s3.cn-north-1.jdcloud-oss.com/material/6ace2b86e4b0e7f3f4bc8666.pdf)。各章节页数为官方建议，不是必须逐项占满；主稿合计不超过20页。

|要求|本版位置与处理|
|---|---|
|项目背景、问题与价值|P1–2：技术文献研读/复用场景，五类业务产物|
|2–3类数据来源与知识内容|P2及资料附件：公开论文、技术手册、QASPER外部参考；区分业务资料与验证集|
|预处理流程图及工具/API|P5–6：直传、SHA核验、Outbox、解析归一、编译索引；P3/P12/P13说明服务与接入|
|方法、理由与分析流程|P7–10：RRF/切面轮转、结构化主张、字段数值见证、Wiki修订；公式/协议示例可见|
|项目架构与关键实现|P3–16：组件、ER、时序、数据流、版本轴、状态转换与取舍；详细源码索引另附|
|1–2项创新点|P16：证据生命周期与授权协作两项工程组合；上游模型与标准组件分列|
|实际结果、价值、问题与改进|P17–19：既有统计和三类实际输出；明确复杂版面、多主题覆盖、服务稳定性改进重点|
|风险及缓解|P8–10：结构/证据约束、三态、依赖过期；P13–15：原生许可、资料转发策略、持久任务与条件提交|
|应用UI|P18：真实工作台保存截图|
|至少3组主题相关提示与输出|P19及案例附件：问答、Schema抽取、主题Wiki；保存完整输入和对应结果|
|应用网址与评审账号|按用户要求从PPT移除历史入口和页脚；有效地址与账号在报名平台单独提供，提交前核验可用性|
|匿名性、格式|主稿无团队身份；20页、16:9；正式文件名按真实报名资料改名。第三方文献署名保留|
|成员视频陈述|02提供两版340秒、1080p30fps无音轨MP4；03提供配音稿与字幕。成员加入声音后核对≤360秒及≤300MB|

材料专业性与完整性的内部评分，和正式提交前的真人视频、运行入口、报名身份条件分开记录。后者未完成时不宣称整套报名提交已完成。
