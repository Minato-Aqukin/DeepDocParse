# 项目介绍版提交说明

## 材料用途

主稿介绍DeepDocParse的定位、功能、架构及关键实现。P3–16采用原生可编辑结构图、ER关系图、处理时序、状态图和部署数据流；P18–19集中展示实际界面与三组输入输出。技术来源与详细边界放附件，不再把主稿做成操作培训或审计报告。

|文件|用途|
|---|---|
|01中的PPTX|正式演示主稿；图形和文字可编辑|
|01中的PDF|同一PPT经LibreOffice实际导出，供预览和备份|
|02中的两版MP4|已完成的5分40秒画面；带字幕版可直接加人声，无字幕母版用于调整字幕|
|03中的配音稿、时间表与SRT|成员配音使用；字幕按真实音轨微调|
|04中的逐页PNG|需要延长或缩短某页时使用的清晰画面|
|05中的技术说明、源码索引、案例与资料说明|技术备答和来源附件|
|06中的参赛信息填写稿|内部填写参考，不作为匿名作品附件上传|
|07中的评审记录|主稿内部模型评审，不是赛事官方评定|

## 正式提交要求

- PPT不超过20页，16:9，不超过50MB。
- 文件名按真实报名信息改为`【命题领域-学校-队长姓名-作品名称】`；这些身份不进入匿名正文。
- 成员本人陈述的MP4，实际时长≤6分钟、文件≤300MB。现有两版视频均为1080p、H.264、30fps、5分40秒且没有音轨；只需加入成员声音，无需重新录屏。配音后建议保留H.264视频并使用AAC音频。
- 提交可实际使用的Agent地址和有效评审账号；提交前应以评审身份核验登录、上传、问答、抽取、Wiki及出处访问。入口与账号在报名平台单独提供，不放入匿名PPT、视频或公开仓库。
- 学校、队长、成员、组别、领域、指导教师及签署信息以真实报名系统为准。当前材料未取得该报名会话，不能替团队填造信息或签名。

## 录制顺序

1. 按口播稿完整试读；技术页解释因果，不逐个念字段和函数名。
2. 给02中的视频添加本人录音。P18–19是已保存的真实任务结果，无需重新录屏或录长时间操作。
3. 按真实音轨调整SRT；从头播放导出MP4，确认声音、尾帧、时长和大小。
4. 将正式文件名、可用入口及账号填入提交系统后再上传。当前材料齐备不等于真人视频、报名或在线服务已完成。
